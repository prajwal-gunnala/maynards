1. Silicon Micro-Architecture & The Shared Bus Bottleneck

A flagship mobile phone is not a miniature server with PCIe-attached VRAM. The CPU, GPU, and NPU exist on a single monolithic silicon die and share a unified physical LPDDR5X memory bus. This single hardware reality dictates every compiler optimization decision.

2. The Roofline Model: Why Phone GPUs Fail at Decode

In distributed LLM execution, inference consists of two fundamentally distinct computational regimes:

1. Prompt Prefill (Reading)

Compute-Bound: Matrix × Matrix ($GEMM$)

When ingesting a prompt of $N$ tokens, the model computes across all $N$ tokens simultaneously. Arithmetic intensity is high:

$$\text{Intensity} = \frac{\mathcal{O}(2 \times \text{batch} \times \text{weights})}{\text{Weight Bytes Read}} \gg 1$$

Result: Adreno 840 GPU computes at 3.2× faster prefill speed than the CPU.

2. Token Generation (Writing)

Memory-Bound: Matrix × Vector ($GEMV$)

During autoregressive decoding, exactly 1 token is generated per forward pass. The engine must read the entire 18.56 GB weight matrix through the bus just to perform 1 vector multiply:

$$\text{Intensity} = \frac{\mathcal{O}(2 \times 1 \times \text{weights})}{\text{Weight Bytes Read}} \approx 0.5 \text{ FLOP/Byte}$$

Result: Adreno 840 GPU is 21% slower than Kryo CPU due to driver launch overhead and kernel dispatch synchronizations.

3. The Bayesian Search Optimizer (Optuna TPE Engine)

Rather than relying on static heuristic guesses, the Mesh Compiler drives an automated Bayesian optimization loop over the target hardware across 6 orthogonal search dimensions:

Parameter Search Space Hardware Mechanism Affected
backend opencl vs cpu Selects libmesh_rpc_opencl.so (Adreno GPU) or libmesh_rpc.so (Kryo CPU).
-ngl (GPU Layers) $0 \le \text{ngl} \le N_{\text{layers}}$ Controls how many transformer blocks are offloaded to Adreno OpenCL kernels.
threads $4, 6, 8$ cores Prevents thread contention. 6 threads (big cores only) beats 8 threads by avoiding Cortex-A55 Little-core stalls.
kv_type f16 vs q8_0 Quantization precision of Key-Value attention cache in RAM.
ubatch $128, 256, 512, 1024$ Micro-batch compute chunk size for prompt evaluation kernels.
cache_prompt true / false Enables prefix KV cache reuse across sequential agent conversation turns.
The Thermal Cooling Guard Constraint
Mobile chips throttle aggressively when skin temperature exceeds 40°C. In sustained testing on iQOO 15, throughput degrades from 11.44 tok/s to 5.29 tok/s over 10 minutes as skin hits 47.5°C. To prevent thermal noise from corrupting Bayesian parameter convergence, the tuner enforces an automated cooldown sleep loop between every trial until battery temperature drops below 38°C.

4. The Quality Gate: 15-Task Verification Engine

Faster inference is completely useless if quantized weights cause logic degradation or hallucinations. The compiler incorporates a deterministic Quality Gate running 15 standardized code generation problems against test harnesses:

Quality Gate Results (Measured)

  • Qwen3 0.6B: 2 / 15 tasks passed (13.3%)
  • Qwen3 1.7B: 7 / 15 tasks passed (46.7%)
  • Qwen3-Coder-30B-A3B: 15 / 15 tasks passed (100.0%)

Crucial Scientific Proof: When Qwen 1.7B was split across laptop + phones, it failed the exact same 8 tasks as the single-device baseline. Splitting introduced zero numerical divergence.
